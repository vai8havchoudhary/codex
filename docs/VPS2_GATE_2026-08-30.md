## Profile blocker discovered by comprehensive setup testing

Codex CLI 0.149.1 rejected both generated profiles because `cliproxy-models` 1.0.0 wrote legacy `[profiles.<name>]` tables into `~/.codex/config.toml`. Codex 0.134.0 and later load `~/.codex/config.toml` and then overlay `~/.codex/<profile-name>.config.toml`; the legacy selector/table form is rejected.

The earlier provider, MCP, and council PASS does **not** waive this packaging blocker. The 1.1.0 model-plugin correction therefore migrates to a guarded three-file transaction:

```text
~/.codex/config.toml
~/.codex/cliproxy-grok-4-6.config.toml
~/.codex/cliproxy-gemini-3-7-flash.config.toml
```

A fresh exact-main VPS2 reinstall and council rerun remains required before `v2.0.0` release adjudication.
