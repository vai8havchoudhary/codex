# Privacy

These are local Codex plugins. They do not operate a hosted service and do not collect telemetry.

`cliproxy-models` contacts the configured CLIProxyAPI endpoint, selected through `CLIPROXY_URL` or an existing Codex provider. It reads `CLIPROXY_API_KEY` from the current process environment for authenticated catalog requests, never prints its value, and does not add its value to local configuration. Configuration stores only the environment-variable name as the credential reference. No plugin reads or enumerates proxy account files.

The seven-file configuration transaction stores the base provider/default, five model/council overlays, and `cliproxy-council-models.json` beside the selected base configuration. Named `luna-grok` and `grok-gemini` overlays include root-only `developer_instructions` and a `model_catalog_json` pointer. The derived JSON snapshot retains the selected models' full live Codex descriptors, including capabilities and model instructions, unchanged; it does not synthesize capabilities or add credentials. Server-supplied descriptors are not redacted by this storage mechanism, so inspect snapshots and backups before sharing. Configuration and snapshot writes/backups use mode `0600`.

`codex-moa` coordinates native Codex agents only in the supported Luna-to-Grok and Grok-to-Gemini-High directions. Its checkpoint MCP server stores compact execution records locally beneath `CODEX_HOME`; it receives no proxy key and cannot call models or execute commands. It rejects forbidden sensitive fields and recognizable secret patterns, but is not a general-purpose redactor. Callers must not submit credentials, account data, cookies, tokens, or environment dumps.

Checkpoints may contain repository paths, commands, validation summaries, decisions, and risks supplied by the active Codex session. Schema-2 native witnesses also contain actual agent IDs, exact model IDs, returned verdicts, response summaries, transcript references, and reviewed revisions. These are local evidence claims, not authenticated attestations; checksums verify stored payload integrity, not whether the claimed native event occurred. Independently audit actual runtime events before treating a run as successful. Schema-1 historical records remain read-only, including Gemini-led history; new runs require schema 2 and fresh verification.

Checkpoint files use mode `0600` beneath a mode-`0700` directory. The plugins do not upload checkpoints or model-catalog snapshots as telemetry. However, native Codex execution and user-directed sharing may send task context to the configured upstream model provider. CLIProxyAPI, Codex, and upstream model providers remain subject to their own privacy terms.
